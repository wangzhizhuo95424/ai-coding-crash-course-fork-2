# 课时评价（lesson reviews）— Spec

Status: ready-for-agent

## Problem Statement

用户想让「学生能对自己有权限访问的课时发表评论，讲师也能在同一处评论」。当前课时页只有视频与 Markdown 正文，没有任何用户生成内容能力：没有评价表、没有 service、没有 UI、没有路由接线。仓库里另有一套「课程级星级评分」半成品（checkpoint 产物）：建了表、写了 service 与组件，却因 schema 未导出、migration 未登记而完全断线，容易让人误以为评分能力已存在。此外基线 `npm run test` 与 `npm run typecheck` 已经是红的（23 个失败用例、2 条类型错误），用户不希望这个新功能背上修历史债的责任。这个仓库是教学用途，需要的是 ≤10 分钟能讲透、立刻看得见结果的一个小增量，而不是一次大改造。

## Solution

在课时页新增「课时评价」区块：对**课程内容**打 1~5 整数星（必填）+ 可选文字（10~500 字纯文本），每位用户对每个课时只能有一条活跃评价，可随时编辑、可软删除。每条评价展示自己的星级；学生侧显示作者姓名与头像，讲师侧剥离作者身份。课程讲师（`courses.instructorId`）可对每条评价写一条公开回应。不做任何聚合数字、不做通知、不做治理。用一张新表、一个 service、一处 UI、一组单测完成，走手写 migration，完全不碰既有的课程评分 checkpoint。

## User Stories

1. 作为已登录的学生，我想要给这节课时打 1~5 的整数星，以便表达对课程内容的评价。
2. 作为已登录的学生，我想要在打分之外可选地写 10~500 字纯文字评价，以便说明打分理由。
3. 作为已登录的学生，我想要只打星不写文字也能提交，以便快速反馈。
4. 作为已登录的学生，我想要在分数非整数或超出 1~5 时被明确拒绝，以免脏数据入库。
5. 作为已登录的学生，我想要文字少于 10 字或多于 500 字时收到校验提示，以便写出合适长度的评价。
6. 作为已登录的学生，我想要对同一课时再次提交时覆盖我原来的评价而不是新增一条，以便保持「一人一课时一条」。
7. 作为已登录的学生，我想要随时修改我的星级与文字，以便评价随学习进展更新。
8. 作为已登录的学生，我想要评价上只显示「最后编辑时间」、不显示完整编辑历史，以便界面保持简单。
9. 作为已登录的学生，我想要删除自己的评价后仍看到「该评价已删除」占位，以便列表结构不被打乱。
10. 作为已登录的学生，我想要删除后可以重新提交一条新评价，以便改主意时能重来。
11. 作为已登录的学生，我想要星级与文字一起编辑、不能单独改分，以便评价内容保持一致。
12. 作为浏览课时的学生，我想要在课时页直接看到其他人的评价列表，以便不离开页面就能判断课时质量。
13. 作为浏览课时的学生，我想要每条评价都显示它自己的星级，以便逐条判断。
14. 作为浏览课时的学生，我想要评价区不出现任何平均分、评分人数、星级分布或卡片星级，以便 v1 保持简单。
15. 作为浏览课时的学生，我想要列表按最新发布在前，以便先看到最近的反馈。
16. 作为浏览课时的学生，我想要 v1 只展示最新 20 条且不需要翻页，以便页面轻量。
17. 作为浏览课时的学生，我想要在评价区顶部固定看到「我的评价」卡片，以便一眼找到自己那一条。
18. 作为已评价的学生，我想要在「我的评价」卡片里直接内联编辑，以便不用跳到别的页面。
19. 作为尚未评价的已登录学生，我想要在同一张卡片里直接提交，以便少一次点击。
20. 作为浏览课时的学生，我想要看到其他评价者的姓名与头像，以便判断评价来源。
21. 作为未登录访客，我想要仍能阅读课时评价（与课时正文现状一致），以便在报名前了解口碑。
22. 作为浏览课时的学生，我想要评价文字按纯文本渲染，以便不被 HTML/Markdown 注入影响。
23. 作为该课程的授课讲师，我想要对每条学生评价写一条公开回应，以便解答疑问或说明改进。
24. 作为该课程的授课讲师，我想要回应与学生评价在界面上明显区分，以便读者不会混淆。
25. 作为该课程的授课讲师，我想要随时编辑我的回应，以便修正措辞。
26. 作为该课程的授课讲师，我想要不能删除回应、只能清空内容并保留占位，以便记录不出现断层。
27. 作为该课程的授课讲师，我想要回应限制为 500 字纯文本，以便保持简洁。
28. 作为该课程的授课讲师，我想要学生删除其评价时我的回应一并隐藏，以免出现孤立回应。
29. 作为该课程的授课讲师，我想要学生修改其评价文字时我的回应保持不变，以免被意外覆盖。
30. 作为该课程的授课讲师，我想要只有我这门课的 `instructorId` 能写回应，以便责任明确。
31. 作为其他课程的讲师、平台管理员或学员团队管理员，我不应能写回应，以便权限边界清晰。
32. 作为授课讲师，我想要学生侧看不到评价者真实身份（只显示「已完成该课时的学员 · 日期」），以便学生敢给低分。
33. 作为授课讲师，我想要仍能看到评价的星级、文字与日期，以便据此改进内容。
34. 作为平台管理员，我想要真实身份仍保留在数据库里可查，以便日后核实访问权限与防刷。
35. 作为已登录用户，我想要提交评价时系统强制校验登录状态，以便每条评价都能归属到账号。
36. 作为未登录访客，我想要尝试提交时被拒绝，以免产生无法归属的匿名内容。
37. 作为授课讲师，我想要不能编辑、删除或隐藏学生的评价，以便评价可信。
38. 作为平台管理员，我想要 v1 不提供删除评价的界面，以便治理范围不被偷偷扩大。
39. 作为平台管理员，我想要接受 v1 没有举报、审核、敏感词与限流界面，以便范围可控（滥用内容只能改库）。
40. 作为学生，我想要不收到任何「讲师已回复」通知、自行回到课时页查看，以便 v1 不引入通知基础设施。
41. 作为授课讲师，我想要不收到新评价提醒，以便 v1 不引入通知基础设施。
42. 作为仓库维护者，我想要新表独立于既有的课程级评分表，以便两种评价形态不互相污染。
43. 作为仓库维护者，我想要完全不改动既有的 0003 checkpoint 产物，以便教学练习流程不被破坏。
44. 作为仓库维护者，我想要新增一条手写 0004 migration 并只在 journal 追加一条记录，以便 `db:migrate` 与测试夹具能建出新表。
45. 作为仓库维护者，我想要 seed 脚本的 DROP 列表同步新表，以便 `db:seed` 后不留残表。
46. 作为仓库维护者，我想要避免运行 `db:generate`，以免覆盖 checkpoint 的 snapshot。
47. 作为仓库维护者，我想要把基线 23 个失败用例与 2 条类型错误记入 handoff 而不在本功能修复，以便新功能不背历史债。
48. 作为仓库维护者，我想要验收只看「新增测试全绿 + typecheck 不新增错误 + 失败集合不扩大」，以便不修基线也能验证本次改动。
49. 作为仓库维护者，我想要权限判定抽成 service 层纯函数，以便能在现有测试 seam 上验证。
50. 作为仓库维护者，我想要不引入 loader/action 级新测试，以便只保留一个 seam。
51. 作为课程学员，我想要这次改动保持「10 分钟讲透一个小点」的节奏，以便符合教学约束。
52. 作为课程学员，我想要这个「课时级 5 星 + 文字 + 无聚合 + 讲师一次性回应」的第三种形态被记进 feature ideas，以便不与仓库里已有的「课程级带均分评价」和「课时讨论区」混淆。

## Implementation Decisions

- 采用 React Router Framework mode 的 loader（读）/ action（写）模式：在课时页 loader 中读取评价列表与「我的评价」，在同一路由的 action 中用 `intent` 区分提交/编辑/删除评价与提交/编辑回应；沿用 zod 表单校验封装与 `throw data(..., { status })` 的错误约定。
- 新增 `lesson_reviews` 表（在 Drizzle schema 中声明）：`id`、`user_id`、`lesson_id`、`rating`（1~5 整数）、`body`（可空纯文本 10~500 字）、`created_at`、`updated_at`、`deleted_at`（软删除占位）、`response_body`、`response_at`、`response_by`。讲师回应作为同一行的可空列，**不单独建表**。唯一约束采用 partial unique `(user_id, lesson_id) WHERE deleted_at IS NULL`，使软删除后可重新评价。
- 星级与文字一起 upsert（`onConflictDoUpdate`），不提供「单独改分」接口；不做半星、不做 10 分制。
- 不做任何聚合查询：不调用既有的 `avg`/`count` 汇总函数，不接线既有的只读星级组件与课程评分表单。
- 列表按 `created_at DESC`、`limit 20`，无分页 UI、无排序选择器、无「加载更多」。
- 权限最小实现：写路径强制 `getCurrentUserId`；**不**校验报名、**不**校验 `isLessonCompleted`、**不**校验 `CourseStatus`（完整门控后置）。读路径不加门控，与课时正文现状一致。
- 讲师回应权限：仅当当前用户 id 等于该课程 `instructor_id`；`admin` 与其他 `instructor` 角色只读；`team_members` 的 admin 属**学员团队**角色，不授予写回应权限。
- 署名投影：学生侧 join `users` 取 `name` 与 `avatarUrl`；讲师侧渲染时剥离作者字段，只显示「已完成该课时的学员 · 日期」。真实身份只保留在数据库，admin 通过查库获取，v1 不做界面。
- 讲师回应：每条评价最多 1 条，可编辑、不可删除（可清空内容并保留占位）；学生软删除评价时回应一并隐藏；学生编辑评价不动回应。
- 治理：v1 无隐藏/举报/审核状态列、无审核台、无敏感词、无限流界面；讲师与 admin 都不能编辑或删除学生评价。明确接受「滥用内容只能改库」，并写入产品说明。
- 通知：不引入站内信、邮件、未读角标或 WebSocket；不做任何提醒。
- 数据生命周期：v1 不做课时/课程删除时的级联清理，已知后果是存在评价时删除课时会被外键挡住；不做用户删除/停用/匿名化（仓库本身无此能力）；不做课程复制时的评价迁移与历史数据回填。
- 与既有课程评分的关系：新建独立表，**完全不碰** `course_ratings` 相关代码、0003 migration 与其 snapshot，也不接线课程级评分组件与汇总函数。
- Migration：手写编号 0004 的 SQL，仅在 journal 追加一条记录（tag 指向 0004），同步 seed 脚本的 DROP 列表；不生成 snapshot，并把「`db:generate` 在 0003 不一致解决前不可用」写入 handoff。理由：journal 目前只登记到 0002，直接 `db:generate` 会以 0002 为基线生成新的 0003 并覆盖 checkpoint 的 snapshot。
- 教学形态：这是第三种形态，与仓库 feature ideas 中的「课程级带均分评价」和「课时讨论区」都不同；新增一条 idea 记录以免混淆。
- 术语与文档：`GLOSSARY.md` 目前无正式词条，本 spec 沿用其「待收录候选」措辞（loader、action、schema、migration、seed、checkpoint、SSR）；仓库无 ADR 目录，因此没有 ADR 约束需要遵循。
- 验收基线：`npm run test` 现有 23 红 / 614 绿（14 个来自断线的课程评分、9 个来自独立代理子项目），`npm run typecheck` 现有 2 条 `courseRatings` 错误；全部记入 handoff，不在本 spec 修复。
- 不修改教学材料目录、`lessons/` 与独立代理子项目；不执行 cherry-pick。

## Testing Decisions

- **好测试的定义**：只测外部可观察行为——给定输入与数据库状态，断言返回值、抛出的错误、以及数据库最终的行；不测实现细节（不 mock service 内部函数、不断言某个 Drizzle 方法被调用、不复制 SQL 文本做字符串比较）。
- **唯一 seam**：新 service 模块的公共 API（提交/编辑/软删除评价、列出评价、保存讲师回应，以及同模块导出的权限判定纯函数）。这是仓库现有**最高**可测 seam；loader/action 层没有现成 seam，新建会变成第二个 seam，因此不建。权限逻辑抽成纯函数放到同一个模块，正是为了让它能在同一个 seam 上被测，而不是新开一个 seam。
- **被测模块**：课时评价 service（含权限判定纯函数）；migration 与 journal 的一致性由测试夹具建库过程间接覆盖。
- **覆盖场景**：1~5 边界与非法值、`(user, lesson)` 唯一与 upsert、文字长度校验、软删除占位与删除后可重建、列表按 `created_at DESC` 且 limit 20、讲师回应仅 `instructorId` 可写且每评价最多一条、学生软删除时回应隐藏、未登录写被拒、学生侧与讲师侧署名投影差异、不产生任何聚合结果。
- **Prior art**：既有的课程评分 service 测试（mock db 模块 + `:memory:` SQLite 跑真实 migration、`beforeEach` 重建库、断言数据库最终行）与报名 service 的「校验抛错」测试范式。沿用同目录、同命名、同夹具，不引入路由级测试。
- **验收**：新 service 的 Vitest 测试全绿；`npm run typecheck` 不新增错误；`npm run test` 的失败集合不比基线扩大；loader/action 接线靠手动验收。

## Out of Scope

- 任何聚合展示：平均分、评分人数、星级分布、课程卡片/课程详情页星级、加权、按完成度筛选、排序选择器。
- 完整访问门控：读需登录+报名、写需已完成课时、draft/archived 课程隐藏评价区、PPP 地区门禁在评价区的适配。
- 治理与审核：举报、隐藏/下架状态、审核台、审计日志、敏感词、接口限流、admin 删除界面、真实身份查询界面。
- 通知：站内信、邮件、未读角标、WebSocket 实时更新。
- 讨论型能力：多层回复、学生之间互评、点赞/「有用」、@提及、置顶或标记答案、锚点评论（段落或视频时间戳）。
- 富文本与附件：Markdown、代码块、图片、链接预览。
- 数据生命周期：课时/课程删除时的级联清理、用户删除/停用/匿名化、课程复制时评价迁移、历史数据回填。
- 修复既有断线：`course_ratings` 的 schema 导出、0003 journal 登记、其组件与汇总函数的路由接线、其 14 个失败测试；独立代理子项目的 9 个失败测试；`npm run typecheck` 的 2 条既有错误。
- cherry-pick `course-star-ratings` checkpoint；修改教学材料目录、`lessons/`、独立代理子项目。
- 分页 UI（页码/加载更多）、独立「我的评价」路由。
- 性能调优、生产部署、Stripe、真实登录（均在仓库 mission 的 out of scope 内）。

## Further Notes

- 基线是红的，且是既有状态、不是本 spec 引入。验收刻意改为「不扩大失败集合」；handoff 里需记录 0003 不一致、`db:generate` 暂不可用，以及 `npm run db:seed` 会清空全库（有本地数据时不要随手跑）。
- 教学仓库约束（`MISSION.md` / `NOTES.md`）：全栈新手、每节 ≤10 分钟、一次只讲一个小点、要求立刻可见成果、简体中文且技术术语保留英文原名。本 spec 即按「一张表 + 一个 service + 一处 UI + 一组单测」切分；完整门控、级联删除、加载更多排后续增量。
- 决议：讲师一次性公开回应**纳入 v1**（作为评价表上的可空列），以兑现用户最初「讲师也能评论」的需求；同时保留「写操作需登录」这条最小服务端校验。
- 已知限制：v1 存在评价时删除课时会被外键挡住；游客可读评价；讲师侧看不到评价者身份但真实身份仍在数据库。
- 术语表目前无正式词条；等用户在练习中正确使用这些词后，再按术语表规则收录。仓库无 ADR 目录，无 ADR 约束。
