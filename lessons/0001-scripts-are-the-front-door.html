第 1 课 · 约 8 分钟 · 官方 Section 1「Before We Start」

从 package.json 出发，把项目跑起来

今天只练一个技能：把一个陌生的 npm run X 拆回它真实的命令，并说出它动了哪个文件。做完之后，你会在 http://localhost:5173 看到这个课程平台，而且知道它的数据是从哪来的。

本课路线： 为什么先学这个 → 最小知识 → 动手 5 步 → 回想练习 → 主阅读

为什么先学这个

官方课程后面每一节，都会让你指挥 AI 助手去读代码、改代码、加功能。要判断它说得对不对，第一件事就是知道这个项目到底是怎么被启动的、页面上的数据从哪来。否则助手说「跑一下 db:migrate 就好」，你连它会改什么文件都没法核实。

而 package.json 的 scripts 恰好是你唯一已经动手用过的东西（npm / 命令行）：它是整个项目的「前门」，也是让 AI 助手勘察陌生代码库时最自然的起点。今天从这个门口进去。

最小知识：四条命令，各自动了什么

先记住一句话：scripts 字段是快捷方式表。npm run dev 不是什么神秘操作，它只是去 package.json 里找到 "dev" 这一行，把后面的字符串交给 shell 执行。npm 还会把 node_modules/.bin 临时加进 PATH，所以脚本里可以直接写 react-router、tsx 这种命令名。这是 npm 官方 Scripts 文档写明的机制。

命令真实命令落到哪里
npm install按 package-lock.json 装依赖写 node_modules/
npm run db:migratedrizzle-kit migrate读 drizzle.config.ts 和 drizzle/*.sql，在 data.db 里建表
npm run db:seedtsx scripts/seed.ts先删表重建，再灌入课程、用户、课时等示例数据
npm run devreact-router dev启动 SSR 开发服务器，监听 5173 端口

把中间两条连起来看，数据是这样到页面的：

01app/db/schema.ts 用代码定义表结构
02drizzle/*.sql 是建表剧本，db:migrate 把它演到 data.db
03scripts/seed.ts 灌示例数据；app/db/index.ts 负责打开这个库
04npm run dev 启动应用，页面从库里读数据渲染出来

依据 Drizzle Kit 官方文档：generate 负责生成 SQL 迁移文件，migrate 才把它们应用到数据库。本项目已经生成好了 3 个迁移文件，所以你只需要 migrate。

一个必须记住的危险点

scripts/seed.ts 第 47–69 行会先执行 DROP TABLE IF EXISTS 删掉全部表（连迁移记录表一起），再重建并灌数据。所以 db:seed 不是「补充一点示例数据」，而是清库重来。本地数据有用时别随手跑。

你的环境已经准备好了

当前工作副本里 node_modules/ 和 data.db 都已经存在，Node 是 v24.14.1、npm 是 11.21.1（官方要求 Node 22+，已满足）。所以今天只需要跑 npm run dev，不用重装依赖，更不要重新 seed。上面四条命令是让你读懂「第一次克隆项目时发生了什么」。

顺便练一次工程师的核对习惯

本地 README.md 写的是 React Router v7 + Ably 实时在线，但 package.json 里实际是 react-router 8.3.0，依赖里也没有 Ably。文档会过时，代码不会。官方课程整门课都在教这件事：拿代码核实助手和文档的说法，而不是照单全收。

动手 5 步

照着做，每完成一步就打勾（进度会保存在本地，下次打开还在）。

  • 在 PowerShell 里进入项目根目录并启动：
    cd 'i:\code_space\ai-coding-crash-course'
    npm run dev
    看到 Local: http://localhost:5173/ 就是成功。
  • 浏览器打开 http://localhost:5173，再点进 /courses，确认能看到课程列表 —— 这些课程就是 db:seed 灌进去的。
  • 用编辑器打开 package.json，找到 scripts.dev，把等号右边的真实命令念出来。
  • 向 AI 助手提这个问题（只让它读，不让它改）：
    「只看 package.json、drizzle.config.ts 和 scripts/seed.ts，说明四条启动命令分别读写了哪些文件，不要修改任何文件。」
    这一步就是官方课程后面反复要练的核心动作：先让助手勘察，再自己核实。
  • 拿它的回答和上面那张表对一遍。有对不上的地方，把原话发给我，我们单独补一小课。

验证完可以按 Ctrl+C 停掉服务器，也可以留着继续往下学。

主阅读

今天最值得花 3 分钟读的一手资料： npm Docs · Scripts。重点看两段：Description（npm run 执行 scripts 里的同名命令）和 Environment → PATH（依赖的可执行文件为什么能直接写在脚本里）。读完再回来看本项目的 package.json，会有「原来是这么串起来的」的感觉。

配套对照：上游官方仓库 README 的 Getting Started、官方课程页（确认六章结构与课程定位）。

这一课拿到的东西：项目已经在浏览器里跑起来了，而且你能指着 package.json 说出 npm run dev 背后发生了什么。下一课我们会用同样的办法，把官方课程的 reset <slug> / cherry-pick <slug> checkpoint 流程拆开。
